## 🛡️ 重组检测流程

```
                    ┌───────────────────────┐
                    │  处理新区块 Block M    │
                    └──────────┬────────────┘
                               │
                               ▼
                    ┌───────────────────────┐
                    │  获取父区块哈希        │
                    │  parentHash = M.parent │
                    └──────────┬────────────┘
                               │
                               ▼
                    ┌───────────────────────────┐
                    │  从数据库获取上次保存的哈希  │
                    │  savedHash = DB.lastHash   │
                    └──────────┬────────────────┘
                               │
                               ▼
                    ┌───────────────────────┐
                    │  parentHash ==        │
                    │  savedHash?           │
                    └──────────┬────────────┘
                               │
                  ┌────────────┼────────────┐
                  │ Yes                     │ No
                  │ 正常                     │ 重组！
                  ▼                         ▼
        ┌──────────────────┐     ┌──────────────────────────┐
        │  继续正常处理      │     │  检测重组深度             │
        │                  │     │                          │
        │  1. 解析交易      │     │  reorgDepth = 0          │
        │  2. 更新状态      │     │  currentBlock = M        │
        │  3. 保存哈希      │     │                          │
        └──────────────────┘     │  while (currentBlock !=   │
                                 │         savedBlock):      │
                                 │    reorgDepth++           │
                                 │    currentBlock = parent  │
                                 │                          │
                                 └──────────┬───────────────┘
                                            │
                                            ▼
                                 ┌──────────────────────────┐
                                 │  回滚受影响的充值          │
                                 │                          │
                                 │  UPDATE PendingDeposit   │
                                 │  SET status = 'REORGED'  │
                                 │  WHERE blockNumber >     │
                                 │        savedBlock        │
                                 │  AND status != 'CREDITED'│
                                 └──────────┬───────────────┘
                                            │
                                            ▼
                                 ┌──────────────────────────┐
                                 │  重置监听位置              │
                                 │                          │
                                 │  lastProcessedBlock =    │
                                 │    M - reorgDepth - 6    │
                                 │    (回退到安全区块)        │
                                 └──────────┬───────────────┘
                                            │
                                            ▼
                                 ┌──────────────────────────┐
                                 │  发送告警通知              │
                                 │  "检测到区块重组,深度=X"   │
                                 └──────────┬───────────────┘
                                            │
                                            ▼
                                      (重新处理)
```

## ⏱️ 时间线示例

**以 100 USDT 充值为例**:

```
时间轴 (Arbitrum Sepolia 区块时间 ~0.25s)
─────────────────────────────────────────────────────────────>

T+0s     │ 用户在外部钱包发起转账
         │
T+0.5s   │ ⛓️  交易打包进区块 N
         │     └─> 监听服务检测到: PENDING (0/6)
         │
T+0.75s  │ ⛓️  区块 N+1
         │     └─> 更新: PENDING (1/6)
         │
T+1.0s   │ ⛓️  区块 N+2
         │     └─> 更新: PENDING (2/6)
         │
T+1.25s  │ ⛓️  区块 N+3
         │     └─> 更新: PENDING (3/6)
         │
T+1.5s   │ ⛓️  区块 N+4
         │     └─> 更新: PENDING (4/6)
         │
T+1.75s  │ ⛓️  区块 N+5
         │     └─> 更新: PENDING (5/6)
         │
T+2.0s   │ ⛓️  区块 N+6 ✅
         │     └─> 达到 6 个确认！
         │     └─> 开始入账处理...
         │
T+2.1s   │ 💾 数据库事务:
         │     1. User.fundingBalance += 100
         │     2. CREATE Transaction (DEPOSIT)
         │     3. UPDATE PendingDeposit (CREDITED)
         │     └─> COMMIT
         │
T+2.2s   │ 📢 推送通知给用户
         │     "您的 100 USDT 充值已到账"
         │
         ▼

总耗时: ~2.2 秒 (从上链到到账)
```

**对比其他链**:

| 链 | 区块时间 | 确认数 | 总耗时 |
|----|---------|-------|--------|
| **Arbitrum** | 0.25s | 6 | ~2s |
| Ethereum | 12s | 12 | ~2.4分钟 |
| BSC | 3s | 15 | ~45秒 |
| Polygon | 2s | 20 | ~40秒 |

## 🎯 关键要点总结

### 性能指标
- **检测延迟**: < 5 秒（轮询间隔）
- **入账延迟**: ~2 秒（6个区块确认）
- **吞吐量**: 支持 1000+ TPS（批量处理）

### 可靠性保障
- ✅ 断点续传：服务重启不丢数据
- ✅ 幂等性：txHash 唯一约束防重复
- ✅ 事务安全：余额更新原子性
- ✅ 重组检测：自动回滚并重新处理

### 扩展性
- ✅ 多币种：ETH + USDT（易扩展 USDC/DAI）
- ✅ 多链：架构支持 Ethereum/BSC/Polygon
- ✅ 负载均衡：多 RPC 节点轮询
