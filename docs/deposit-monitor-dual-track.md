## ⚡ 核心特性

### 1. 双线程独立运行

**WebSocket 线程**:
- ✅ 启动即实时监听
- ✅ 零延迟处理新充值
- ✅ 永不停止

**轮询线程**:
- ✅ 并行追赶历史区块
- ✅ 批量高效处理
- ✅ 完成自动停止

### 2. 防重复处理机制

```typescript
private processedBlocks: Set<number> = new Set();

// WebSocket 收到新区块
if (!this.processedBlocks.has(blockNumber)) {
  await this.processBlock(blockNumber);
  this.processedBlocks.add(blockNumber);
}
```

### 3. 智能启动逻辑

```typescript
const blocksBehind = latestBlock - lastProcessed;

if (blocksBehind > CATCHUP_THRESHOLD) {
  // 有落后 → 双轨并行
  startWebSocket();  // 监听最新
  startCatchup();    // 追赶历史
} else {
  // 无落后 → 仅 WebSocket
  startWebSocket();
}
```

## 🎯 解决的问题

### ❌ 旧方案（单轨切换）

```
启动 → 轮询追赶 → 追赶完成 → 切换 WebSocket

问题:
1. 追赶期间新充值延迟处理（最多几分钟）
2. 追赶速度慢导致越来越落后
3. 切换时可能丢失区块
```

### ✅ 新方案（双轨并行）

```
启动 → 同时运行:
         ├─ WebSocket: 实时监听新充值 ✅
         └─ 轮询: 追赶历史充值 ✅

优势:
1. 新充值零延迟处理 (<0.5秒)
2. 历史充值并行追赶
3. 追赶完成后自动停止轮询
4. 无缝衔接，零丢失
```

// config.ts

## 📈 性能分析

### 处理速度

**WebSocket 线程**:
- 实时监听，零延迟
- 每个新区块 < 0.5 秒处理

**轮询线程**:
```
配置: BATCH_SIZE=10, 并发=3

每批处理时间:
  10 个区块 ÷ 3 并发 ≈ 4 次批次
  4 × 1 秒 ≈ 4 秒

每批处理 10 个区块，每 5 秒一批
追赶速度: 10 ÷ 5 = 2 区块/秒

新区块产生速度: 4 区块/秒

结论: 轮询速度 < 新区块速度
      但 WebSocket 实时处理新充值 ✅
      历史区块慢慢追赶，不影响实时性 ✅
```

### 内存使用

```typescript
// 防止内存泄漏
if (this.processedBlocks.size > 1000) {
  // 只保留最近 1000 个区块
  const toDelete = Array.from(this.processedBlocks)
    .sort((a, b) => a - b)
    .slice(0, 100);
  toDelete.forEach(b => this.processedBlocks.delete(b));
}
```
